Fresh Grape Traceability PoC - On-chain Demo Script
Estimated speaking time: about 2.5 minutes

==============================
English speaking script
==============================

[Show the Remix screenshots]

Now I will demonstrate the on-chain part of our fresh grape traceability PoC.

Before the integrated demo, we used Remix for manual contract-level validation.
In Remix, we deployed ActorRegistry dot sol first, and then deployed
GrapeTraceability dot sol with the registry address.
The images shown here are selected screenshots from representative function
tests, rather than the complete test record.
The first screenshot shows getActor returning an active Producer role.
The second screenshot shows an authorised contamination action emitting the
BatchFlagged event. The third screenshot shows markRecalled emitting the
BatchRecalled event. These focused checks confirm that actor lookup and the main
safety actions work correctly. Comprehensive verification is provided by our
automated tests, while the complete batch, custody, quality and oracle workflow
is demonstrated next through pnpm demo.

[Switch to the pnpm demo terminal]

Our formal system demo uses pnpm demo because it connects the contracts with the
other components of the PoC.

In step one, the script deploys our two smart contracts on the local Hardhat
blockchain with chain ID 31337.
ActorRegistry manages participant roles and permissions, while
GrapeTraceability manages the grape batch lifecycle.

In steps two and three, the Administrator registers the Regulator. The Regulator
then registers the Producer, Transporter and Retailer.
For every contract call, the terminal shows the caller, function name,
transaction hash, confirmation block and success status.

In step four, the Producer creates batch GRAPE-2026-001.
The initial batch status is Created, and the Producer is the current custodian.

In step five, the Producer transfers custody to the Transporter.
The contract checks the roles and the valid custody route before accepting the
transaction. The batch status then changes to In Transit.

[Scroll to the final trace]

In the final trace, the batch status is Recalled. We can see two custody
transfers, from Producer to Transporter and then to Retailer, as well as two
quality records. This demonstrates traceability, integrity and auditability.

Now my teammate will explain the off-chain temperature computation, file storage
and oracle submission shown in steps six to nine.

==============================
中文理解稿
==============================

[展示 Remix 截图]

现在我将演示新鲜葡萄溯源 PoC 的链上部分。

在进行集成演示之前，我们使用 Remix 对合约进行手动的合约级验证。
我们先部署 ActorRegistry.sol，再将它的地址传入 GrapeTraceability.sol。
这里展示的是代表性函数测试的部分截图，并不是全部测试记录。
第一张截图显示 getActor 返回一个 active 的 Producer 角色。第二张截图显示
授权账户执行污染标记并产生 BatchFlagged event。第三张截图显示 markRecalled
产生 BatchRecalled event。这些针对性测试证明角色查询和主要安全操作能够正确
工作。自动化测试提供系统性验证，完整的批次、custody、质量记录和 oracle
流程将在 pnpm demo 中展示。

[切换到 pnpm demo 控制台]

正式系统演示使用 pnpm demo，因为它能够把合约与 PoC 的其他组件连接起来。

第一步，脚本在 Chain ID 31337 的本地 Hardhat 区块链上部署两个智能合约。
ActorRegistry 负责参与者角色和权限，GrapeTraceability 负责葡萄批次生命周期。

第二和第三步，Administrator 注册 Regulator，然后 Regulator 注册 Producer、
Transporter 和 Retailer。每次调用都会显示调用者、函数名、交易哈希、确认区块
和成功状态。

第四步，Producer 创建 GRAPE-2026-001 批次。初始状态是 Created，当前
custodian 是 Producer。

第五步，Producer 将 custody 转给 Transporter。合约先检查角色以及 custody
路径是否合法，然后接受交易，批次状态变为 In Transit。

[滚动到 Final Trace]

在最终 trace 中，批次状态是 Recalled。我们可以看到两次 custody transfer：
Producer 到 Transporter，再到 Retailer，同时还有两条质量记录。这证明系统
实现了 traceability、integrity 和 auditability。

接下来由我的队友介绍第六到第九步中的链下温度计算、文件存储和 oracle 提交。
